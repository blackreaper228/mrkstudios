# Редактирование портфолио через Pages CMS

Интеграция подготовлена локально. Онлайн-панель станет доступна после публикации конфигурации и подключения GitHub App. Пуш выполняется только по отдельной команде владельца.

## Первое подключение владельцем

1. Опубликовать изменения через терминальные git commit и git push, предварительно согласовав локальную и удалённую историю без потери клиентских правок. Не применять force push.
2. Открыть https://app.pagescms.org и войти через GitHub.
3. Подключить Pages CMS GitHub App, предоставив доступ к репозиторию blackreaper228/mrkstudios.
4. Выбрать репозиторий и ветку main. Конфигурация .pages.yml добавит раздел «Фотографии и заголовки».
5. При необходимости пригласить клиента по email через Collaborators в Pages CMS. Клиенту не нужен аккаунт GitHub. Приглашения отправляет владелец.

## Работа клиента

Открыть раздел «Фотографии и заголовки». В каждом из пяти блоков можно изменить заголовок и загрузить или выбрать фотографию. Затем сохранить изменения. Заголовок обязателен, до 80 символов. Поддерживаются JPG, JPEG, PNG, WebP и AVIF; рекомендуемый размер — 1600 × 900.

Сохранение в CMS создаёт коммит в GitHub. GitHub Pages обновляет сайт после успешной публикации; затем нужно обновить страницу сайта. Порядок пяти блоков соответствует порядку карусели.

## Контент и разработка

- .pages.yml — форма редактора и настройки загрузки.
- docs/content/portfolio.json — основной файл контента, который редактирует CMS.
- docs/uploads — фотографии, загруженные клиентом.
- dist/content и dist/uploads — локальные копии для предпросмотра.

После получения клиентских правок из GitHub и после изменений оформления запускать из корня проекта:

```sh
python scripts/sync-site.py
node scripts/test-content.mjs
```

Скрипт сначала копирует контент из docs в dist, затем обновляет код сайта в docs, не перезаписывая клиентский контент. Не копировать dist целиком поверх docs. При ручной локальной замене контента редактировать docs/content/portfolio.json и запускать синхронизацию.

Сайт читает JSON без сборки. Пути загруженных изображений работают и под /mrkstudios/ на GitHub Pages, и в локальном предпросмотре. При недоступном или некорректном JSON остаются резервные демонстрационные фотографии. Секреты и токены в сайт не добавляются.

Официальная документация: https://pagescms.org/docs/quick-start/ и https://pagescms.org/docs/configuration/collaborators/

## Галереи разделов

Разделы Events, Concerts, Commercials, Documentaries и Food имеют отдельные страницы и собственные файлы docs/content/galleries/*.json. В Pages CMS выбрать нужный раздел и редактировать список «Работы»: добавлять, удалять и менять порядок карточек.

Для каждой карточки указать название и тип. Для типа «Фотография» загрузить изображение. Для типа «Видео» заполнить ссылку MP4, WebM, OGV, M4V, YouTube или Vimeo. Обложка видео необязательна, но рекомендуется для быстрого предпросмотра. У видео на YouTube/Vimeo должно быть разрешено встраивание. Изображения в сетке обрезаются до пропорции 396 / 496; при открытии показываются целиком.


## Управление текущим сайтом

- **Меню и названия разделов**: поменять название, порядок, удалить пункт или вернуть страницу в список; переключатель дополнительной группы отделяет Gear Rental и Team от основных разделов. Страница выбирается из существующих адресов; переименование не меняет URL.
- **Главная — тильт-фотографии, заголовки и ссылки**: у каждого из пяти слайдов редактируются изображение, заголовок и ссылка на раздел или фотосессию.
- **Events / Concerts / Commercials / Documentaries / Food**: список карточек фотосессий. Название, тип обложки, изображение или видео-ссылка. Видео карточки и внутренней страницы используют одну ссылку; Vimeo должен разрешать встраивание.
- **Контент фотосессии** внутри карточки: добавлять, удалять и переставлять фотографии и видео. Для фотографии указать изображение; для видео — ссылку Vimeo, YouTube или MP4. Можно указать подпись и описание фотосессии. Пустой список показывает обложку.
- **Адрес фотосессии**: постоянный уникальный slug; не менять после публикации ссылки. Для старых записей без slug адрес использует позицию карточки.

После сохранения Pages CMS коммитит изменения в main; GitHub Pages публикует обновления. Новые HTML-страницы автоматически не создаются при переименовании меню: названия применяются к выбранным существующим страницам.
